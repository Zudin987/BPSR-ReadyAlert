# v1.33.7 release acceptance gates

This checklist is **not** a declaration of release readiness. Do not merge PR #156 or publish v1.33.7 until its outstanding code issues and validation requirements are closed. Record actual evidence and links in the PR; never mark unperformed tests as passed.

## Cloud chat privacy

- In native Speech & Translation settings, explain that enabling Google translation transmits the message text to Google, and that Google TTS transmits text for speech synthesis. Clarify the applicable channels and that disabling either control stops its own requests.
- Obtain affirmative consent for each service before sending text; make the service default disabled on fresh profiles. Explicitly handle upgrades whose existing `settings.json` contains an enabled value created under older defaults, rather than interpreting it as proven consent. Test fresh, migrated, explicitly opted-in, and opted-out profiles.
- Test TTS-only mode with translation disabled and prove it makes no translation HTTP calls; test translation-only and both-enabled paths. Do not weaken the smoke test's privacy assertions.

## Updater privacy and safety

- Verify default `auto_download=false` in the *generated* updater. Define and test migration for saved `update-settings.json` containing `autoDownload=true`; the old default was true, so persistence alone does not prove an intentional choice.
- Test both manual and automatic update flows on actual Windows, including decline, invalid manifest, SHA-256 mismatch, interrupted download, rollback, and restart. Preserve the existing immutable-version release gate.

## Encounter correctness

- Ensure personal-best comparisons include stable encounter scene/difficulty identity, not only a target name and character spec; avoid claiming a PB when legacy records lack reliable context. Add migration/compatibility and same-name/different-difficulty regression cases.
- Replay representative real packets for encounter rollover, wipe/revive, mechanic identification, food/serum status, and adapter switching. Document packet provenance without uploading private chat or player identifiers.

## Release CI and desktop validation

- Update `rust/Cargo.toml` and the root package version in `rust/Cargo.lock` together to 1.33.7; update release notes. Run the complete Windows CI workflow on the exact final PR head and verify **completed/success** for tests, Clippy, release build, native EXE smoke, 20 MiB size budget, packaging, generated-source and native render artifact uploads.
- Test the actual portable executable in an interactive Windows session with Npcap installed and Blue Protocol running; verify startup/tray, overlays, settings persistence, translation/TTS opt-in, updater behavior, accurate capture, and clean shutdown. CI's `--build-smoke-test` is not a substitute for in-game validation.
- Once all gates have evidence, mark PR ready, satisfy required reviews/checks, merge to `main`, and verify the resulting main-branch CI and Release Rust workflow finish successfully. Confirm the immutable `v1.33.7` tag, published GitHub Release, downloadable ZIP, EXE, `SHA256SUMS.txt`, `update.json`, and EXE checksum consistency. Record the exact merge SHA and workflow URLs.
